Go 后端（`language: go`，crate `tsurara-lang-go`）生成 struct、带常量的具名类型，以及每个操作一个函数，供运行时模块 `github.com/tsurara-openapi/tsurara/runtimes/go`（包 `tsurara`，`runtimes/go`）使用。本页说明映射关系。该后端是实验性的：`tsurara generate` 会这样提示，其输出可能会改变。

生成的代码和运行时只使用标准库（`encoding/json`、`net/http`），并且为了 struct 标签选项 `omitzero` 需要 Go 1.24 或更高版本。Go 是第一个接近最小能力集的语言：没有联合类型、没有继承、没有原生枚举、没有字面量类型，只有指针能区分缺失值和零值。

## 能力 {#capabilities}

`tsurara_lang_go::CAPABILITIES`（design.md 18.5.2）：

| 能力 | 值 | 说明 |
|---|---|---|
| `inline_records` | no | 内联对象变为以其所在位置命名的 struct（`PetOwner`） |
| `structural_unions` | no | 联合类型变为包装 struct（见下文） |
| `tagged_unions` | yes | 同样是包装 struct，但按判别字段解码，而不是逐个尝试成员 |
| `intersections` | no | `allOf` 变为一个复制了字段的 struct |
| `inheritance` | none | 曾考虑过嵌入，但没有采用：`encoding/json` 会静默丢弃 JSON 名称相同的提升字段 |
| `literal_types` | no | `const` 使用其标量类型 |
| `enums` | none | 带常量的具名类型（`EnumRepr::Constants`） |
| `tuples` | no | 列表 |
| `strict_decoding` | no | 具名字符串或整数类型接受任何值，因此枚举无需兜底即是开放的 |
| `nullable_primitives` | yes | 指针 |
| `recursion_by_value` | no | struct 不能包含自身：在闭合循环的字段上使用指针（pass 10）；切片和映射不需要 |

## 值的转换 {#value-conversion}

注解（design.md 18.7）：`encoding/json` 的 struct 标签。标签无法表达的内容（联合类型、额外属性、可选且可空的字段）会生成 `MarshalJSON` 和 `UnmarshalJSON` 方法，它们只调用运行时的通用辅助函数（`tsurara.UnmarshalTagged`、`tsurara.UnmarshalUntagged`、`tsurara.MarshalUnion`、`tsurara.MarshalWithExtra`、`tsurara.UnmarshalWithExtra`）；算法位于运行时中，并由其测试覆盖。OperationDef 中不包含 TypeDef 引用。

`encoding/json/v2`（自 Go 1.25 起的实验特性）可以省去部分辅助函数（它能用 `omitzero` 区分缺失和 `null`，并支持内联映射），但在所支持的最旧 Go 版本中它并不稳定；使用辅助函数可以让生成的代码在能使用 v2 时保持不变。

## 映射 {#mapping}

| 模型 | Go |
|---|---|
| 对象 | `type Pet struct { ... }` |
| 必需属性 | `Name T `json:"name"`` |
| 可选属性 | `Name *T `json:"name,omitzero"`` （`nil` 表示缺失）；切片和映射不使用指针（`[]T`，`nil` 表示缺失，空切片以 `[]` 发送） |
| 可空属性 | `Name *T `json:"name"`` （`nil` 为 `null`） |
| 可选且可空 | `Name tsurara.Nullable[T] `json:"name,omitzero"``，具有 `Missing`、`Null` 和 `Value` 三种状态（`tsurara.Value(v)`、`tsurara.Null[T]()`；Q3） |
| `additionalProperties` | `AdditionalProperties map[string]T `json:"-"``，并生成调用 `tsurara.MarshalWithExtra` 和 `tsurara.UnmarshalWithExtra` 的方法 |
| 只有 `additionalProperties` 的对象 | `map[string]T` |
| 字符串枚举 | `type Status string` 以及 `const ( StatusAvailable Status = "available"; ... )`；其他字符串也会保留 |
| 整数枚举 | `type Level int64` 以及 `const ( Level1 Level = 1; ... )` |
| 带判别字段的联合类型 | 每个成员一个指针的 `type Pet struct { Cat *Cat; Dog *Dog; Unknown json.RawMessage }`；`UnmarshalJSON` 读取判别字段并把整个对象解码到该成员，`MarshalJSON` 写出已设置的成员。`Unknown`（在接收值的位置）保留未列出标签的 JSON；如果有 `defaultMapping` 成员，则改由它接收 |
| 其他联合类型（`oneOf`、`anyOf`、类型数组） | 同样的包装（`Integer *int64; String *string`）；`UnmarshalJSON` 按顺序尝试成员，保留第一个能解码的 |
| `allOf` | 一个包含所有成员字段的 struct |
| 别名 | `type Name = T` |
| `$ref` 循环 | 在闭合循环的字段上使用指针 |
| `integer`（`int32`、`int64`、无）、`number`、`boolean` | `int32`, `int64`, `int64`, `float64`, `bool` |
| `string`（任意格式） | `string`；格式写在文档注释中，类型映射可以指定其他类型（`time.Time`） |
| 数组、映射 | `[]T`, `map[string]T` |
| `{}`、没有 `go` 条目的外部类型 | `any` |
| 二进制 | 发送的位置（请求体、multipart 部分）为 `tsurara.File`（字节、文件名、媒体类型）；响应为 `[]byte` |
| `x-tsurara-type` / 类型映射 | 其中的 `go` 条目，或 `go.typeMappings` 和 `go.overrides`：一个类型及其所在包的导入路径 (`{ type: uuid.UUID, import: { from: github.com/google/uuid } }`, `{ type: time.Time, import: { from: time } }`)，与 073 一样会被检查 |

### 近似 {#approximations}

| 结构 | 近似方式 |
|---|---|
| 不带标签的联合类型 | 第一个能解码的成员胜出；struct 成员在解码时不允许未知字段，这样一个对象不会匹配所有 struct。不检查必需字段 |
| 必需属性 | 解码时不检查：缺失时为零值 |
| 可空的必需属性 | 缺失的值解码为 `nil` |
| `const` | 其标量类型 |
| 元组 | `[]any` |
| 字符串和数字约束、`oneOf` 的互斥性 | 不检查 |
| 带小数写法的整数（`1.0`） | 被 `encoding/json` 拒绝 |
| 名称无法放入 struct 标签的属性（包含 `"`、`\\`、`,`、`'` 或反引号，或为空） | 省略，并给出警告 |
| 带标签的联合类型 | 在接收值的位置添加 `Unknown`；枚举不需要兜底，因为具名类型可以保存任何值 |

## 布局与命名 {#layout-and-naming}

输出目录中只有一个包（Go 无法在不产生导入循环的情况下把一个包拆分到多个目录）。每个声明一个文件（`pet_gen.go`），每个操作一个文件（`get_pet_by_id_op_gen.go`），以及包含包文档和运行时版本的 `tsurara_gen.go`。文件名以 `_gen.go` 结尾，这样不会有文件名以构建约束（`_linux.go`、`_test.go`）结尾。每个文件都以 Go 工具能识别的 `// Code generated by tsurara. DO NOT EDIT.` 开头，并按 `gofmt` 的格式输出（对齐字段、标签和注释），因为后端不运行格式化工具（18.8）。描述会变成去掉缩进和空行的 `//` 注释，这样 gofmt 不会发现需要改写的代码块、列表或标题。

所有内容都会导出：类型、字段、常量和函数使用 PascalCase，并采用 Go 的首字母缩略词（`ID`、`URL`、`HTTP`、`JSON`、`API` 等 golint 列出的词，复数形式也算：`PetID`、`PhotoURLs`、`GetPetByID`）。首字母没有大写形式的名称会加上 `X`（`X日本語`），以数字开头的名称加上 `V`。枚举常量由类型名和值组成（`PetStatusAvailable`）。它们都共享包的作用域。函数保留其操作的名称：同名的 schema 会改名，如果它是该操作的请求体则为 `{Name}Body`（`toggleAll` 与 schema `ToggleAll` 会得到 `ToggleAll(ctx, c, body ToggleAllBody, nil)`），否则为 `{Name}Model`。其他冲突按占用名称的顺序编号（类型、常量，然后是函数）。Go 的关键字和预声明标识符都是小写，因此导出的名称永远不会与之冲突；只有会变成空的名称或以数字开头的名称（`V1`）才会改变。字段按 struct 命名，避开 struct 自身使用的名称（`AdditionalProperties`），并在标签中带上其 JSON 键。

## 调用函数与结果 {#call-functions-and-results}

```go
func GetPetByID(ctx context.Context, c *tsurara.Client, petID int64, opts *GetPetByIDOptions) (*tsurara.Success[Pet], error)
```

- 文档注释以函数名开头（`// GetPetByID calls GET /pet/{petId}.`），后面是摘要和描述。
- context 用于取消调用并携带截止时间。必需参数和必需的请求体是函数参数；所有可选内容都是 `{Operation}Options` 的指针字段，`opts` 可以为 `nil`。
- 有多种媒体类型的请求体是一个包装 struct `{Operation}Body`，每种媒体类型一个指针（`JSON *Pet`、`Form *Pet`、`OctetStream *tsurara.File`）；已设置的字段决定 `Content-Type`。
- `*tsurara.Success[T]` 具有 `Status`、`Data T`、`Headers` 和 `Operation`。`T` 是成功响应体的类型：没有内容的响应为 `struct{}`（或另一个响应类型的零值），类型不同时为 `any`；带 JSON 媒体类型的响应以 JSON 读取（与 Rust 相同）。二进制响应为 `[]byte`，文本响应为 `string`。
- 带有条目 schema（`itemSchema`，或 3.2 之前的 `x-itemSchema`；design.md 8.5）的 Server-Sent Events、JSON Lines 和 JSON text sequences，在所有成功响应都逐条读取时为 `*tsurara.Success[*tsurara.Items[T]]`：函数调用 `tsurara.DoItems`，并在响应头到达后返回，用 `for item, err := range s.Data.All()` 读取条目。事件是一个联合包装，每个事件一个指针（`StreamEvent{StreamNoteEvent *StreamNoteEvent; ...; Unknown json.RawMessage}`），由 `event` 选择；同一事件有多个名称时，是带常量的具名类型（`MixedPingEventNamePong`）。退出循环会关闭响应，`Close` 不读取即关闭，客户端的超时不覆盖读取条目的过程（context 会覆盖）。当流旁边还有 JSON 媒体类型时，该操作按上文所述以 JSON 读取。
- 对于契约中除成功以外的每种结果，错误都是 `*tsurara.Failure[E]`，具有 `Kind`（`tsurara.KindHTTP`、`KindNetwork`、`KindTimeout`、`KindParse`、`KindUnexpected`、`KindAborted`）、`Status`、`Documented`（有定义中声明的错误响应体 `E` 时为它，否则为原始响应体）以及 `Cause`。它可以 unwrap 为原因，因此 `errors.Is(err, context.Canceled)` 可用。对 `var failure *tsurara.Failure[Problem]` 使用 `errors.As(err, &failure)` 可以得到该操作定义中声明的响应体；`var f tsurara.AnyFailure` 可读取任何操作的失败，并提供 `f.Info()`（`Kind`、`Status`、`Documented`、`Headers`、`Cause`、`Operation`）。
- OperationDef 是 `spec/operation-def.schema.json` 的 JSON，以字符串嵌入，并只解析一次（`sync.OnceValue`）。
- `tsurara_gen.go` 记录了代码所需的运行时版本（`// Requires github.com/tsurara-openapi/tsurara/runtimes/go v0.1.0`）；`tsurara check` 会将其与最近的 `go.mod` 中的要求（同一次版本）进行比较，对于被 `replace` 指令指向别处的模块只做报告。
- 参数使用小驼峰（`petID`）；Go 保留的名称或函数自身使用的名称（`type`、`string`、`ctx`、`opts`）会加上编号（`type2`）。Options 的字段与 struct 字段一样导出。

## 选项 {#options}

```yaml
language: go
go:
  package: petstore                              # 默认：输出目录的名称
  runtimeModule: github.com/tsurara-openapi/tsurara/runtimes/go
  typeMappings:                                  # 按格式

    "#/components/schemas/Id": int64
```

## 不使用客户端的类型 {#types-without-the-client}

使用 `operations: false` 时，包中只有声明：没有操作文件，也没有任何导入 `net/http` 或 `context` 的内容。运行时仍是一个包；生成的类型只使用其中的联合类型辅助函数（`types.go`、`value.go`），在没有任何代码调用客户端时，链接器会把客户端排除。这些类型就是普通的 `encoding/json` 类型：

```go
var pet petstore.Pet
err := json.Unmarshal([]byte(`{"id":1,"name":"Pochi"}`), &pet)
```

## Mock {#mocks}

使用 `go.mocks: true` 时，生成的包中会有带构建标签 `tsurara_mocks` 的 `mocks_gen.go`，因此生产构建会排除它，测试则用 `go test -tags tsurara_mocks` 运行：

- `Mock{Type}()` 解码每个声明的示例值。
- 每个操作都有按定义中声明的状态码划分的构造函数（`ShowPetByIDMock200(body Pet)`、`ShowPetByIDMockDefault(status int, body Error)`），以及供 `tsuraratest` 使用的 `ShowPetByIDRoute(respond)`（nil 表示定义中第一个成功响应）；`MockRoutes()` 列出所有操作。

它的名称在包中所有其他名称之后才占用，因此启用 Mock 永远不会让生成的代码改名。

## 使用方法 {#using-it}

生成到你的模块的某个目录中（`output: internal/petstore`），引入运行时（`go get github.com/tsurara-openapi/tsurara/runtimes/go`），然后调用函数：

```go
c := tsurara.NewClient("https://petstore3.swagger.io/api/v3")
pets, err := petstore.FindPetsByStatus(ctx, c, petstore.FindPetsByStatusStatusAvailable, nil)
if err != nil {
	return err
}
for _, pet := range pets.Data {
	fmt.Println(pet.Name)
}
```
