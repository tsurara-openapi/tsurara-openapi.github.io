Goバックエンド（`language: go`、クレート `tsurara-lang-go`）は、struct、定数付きの名前付き型、操作ごとに1つの関数を生成します。関数はランタイムのモジュール `github.com/tsurara-openapi/tsurara/runtimes/go`（パッケージ `tsurara`、`runtimes/go`）を使います。このページでは対応関係を説明します。このバックエンドは実験的です。`tsurara generate` もそう表示し、出力は変わることがあります。

生成コードとランタイムは標準ライブラリ（`encoding/json`、`net/http`）だけを使い、structのタグのオプション `omitzero` のためにGo 1.24以降を必要とします。Goは最小限の能力に近い最初の言語です。unionも継承もネイティブのenumもリテラル型もなく、値がないこととゼロ値を区別する手段はポインターしかありません。

## 能力 {#capabilities}

`tsurara_lang_go::CAPABILITIES`（design.md 18.5.2）：

| 能力 | 値 | 補足 |
|---|---|---|
| `inline_records` | no | インラインのオブジェクトは、置かれた場所にちなんだ名前のstructになります（`PetOwner`） |
| `structural_unions` | no | unionはラッパーのstructになります（後述） |
| `tagged_unions` | yes | これもラッパーのstructで、メンバーを試すのではなく判別子でデコードします |
| `intersections` | no | `allOf` はフィールドをコピーした1つのstructになります |
| `inheritance` | none | 埋め込みも検討しましたが採用していません。同じJSON名を持つ昇格したフィールドを、`encoding/json` が黙って捨てるためです |
| `literal_types` | no | `const` はそのスカラー型になります |
| `enums` | none | 定数付きの名前付き型（`EnumRepr::Constants`） |
| `tuples` | no | リスト |
| `strict_decoding` | no | 名前付きの文字列型や整数型はどの値も受け入れるので、enumは受け皿なしで開いています |
| `nullable_primitives` | yes | ポインター |
| `recursion_by_value` | no | structは自分自身を含められないので、循環を閉じるフィールドにポインターを使います（pass 10）。スライスとマップには不要です |

## 値の変換 {#value-conversion}

アノテーション（design.md 18.7）：`encoding/json` のstructのタグです。タグで表せないもの（union、追加のプロパティ、省略可能かつnullを許すフィールド）には `MarshalJSON` と `UnmarshalJSON` のメソッドを生成します。これらのメソッドはランタイムの汎用ヘルパー（`tsurara.UnmarshalTagged`、`tsurara.UnmarshalUntagged`、`tsurara.MarshalUnion`、`tsurara.MarshalWithExtra`、`tsurara.UnmarshalWithExtra`）を呼ぶだけです。アルゴリズムはランタイムにあり、ランタイムのテストで確かめています。OperationDefにTypeDefの参照は含まれません。

`encoding/json/v2`（Go 1.25からの実験的機能）を使えば一部のヘルパーは不要になります（`omitzero` で値がないことと `null` を区別でき、インラインのマップもあります）。しかし、対応する最も古いGoでは安定していません。ヘルパーを使っておけば、v2が使えるようになっても生成コードは変わりません。

## 対応表 {#mapping}

| モデル | Go |
|---|---|
| オブジェクト | `type Pet struct { ... }` |
| 必須のプロパティ | `Name T `json:"name"`` |
| 省略可能なプロパティ | `Name *T `json:"name,omitzero"`` （`nil` は値がないことを表します）。スライスとマップはポインターにしません（`[]T`。`nil` は値がないことを表し、空のスライスは `[]` として送られます） |
| nullを許すプロパティ | `Name *T `json:"name"`` （`nil` は `null`） |
| 省略可能かつnullを許す | `Name tsurara.Nullable[T] `json:"name,omitzero"``。`Missing`、`Null`、`Value` の状態を持ちます（`tsurara.Value(v)`、`tsurara.Null[T]()`。Q3） |
| `additionalProperties` | `AdditionalProperties map[string]T `json:"-"``。`tsurara.MarshalWithExtra` と `tsurara.UnmarshalWithExtra` を呼ぶメソッドを生成します |
| `additionalProperties` だけのオブジェクト | `map[string]T` |
| 文字列のenum | `type Status string` と `const ( StatusAvailable Status = "available"; ... )`。ほかの文字列もそのまま保持します |
| 整数のenum | `type Level int64` と `const ( Level1 Level = 1; ... )` |
| 判別子付きのunion | メンバーごとに1つのポインターを持つ `type Pet struct { Cat *Cat; Dog *Dog; Unknown json.RawMessage }`。`UnmarshalJSON` は判別子を読み、オブジェクト全体をそのメンバーにデコードします。`MarshalJSON` は設定されているメンバーを書きます。`Unknown`（値を受け取る箇所）は挙がっていないタグのJSONを保持します。`defaultMapping` のメンバーがあれば、代わりにそれが受け取ります |
| そのほかのunion（`oneOf`、`anyOf`、型の配列） | 同じラッパー（`Integer *int64; String *string`）。`UnmarshalJSON` はメンバーを順に試し、最初にデコードできたものを残します |
| `allOf` | すべてのメンバーのフィールドを持つ1つのstruct |
| エイリアス | `type Name = T` |
| `$ref` の循環 | 循環を閉じるフィールドにポインター |
| `integer`（`int32`、`int64`、指定なし）、`number`、`boolean` | `int32`, `int64`, `int64`, `float64`, `bool` |
| `string`（どのフォーマットでも） | `string`。フォーマットはドキュメントコメントに書かれ、型マッピングでほかの型（`time.Time`）を指定できます |
| 配列、マップ | `[]T`, `map[string]T` |
| `{}`、`go` のエントリがない外部の型 | `any` |
| バイナリ | 送る箇所（本文、マルチパートのパート）では `tsurara.File`（バイト列、ファイル名、メディアタイプ）。レスポンスでは `[]byte` |
| `x-tsurara-type` / 型マッピング | `go` のエントリ、または `go.typeMappings` と `go.overrides`。型をそのパッケージのimportパスとともに書きます (`{ type: uuid.UUID, import: { from: github.com/google/uuid } }`, `{ type: time.Time, import: { from: time } }`)。073と同じく検査されます |

### 近似 {#approximations}

| 構造 | 近似 |
|---|---|
| タグなしのunion | 最初にデコードできたメンバーが選ばれます。structのメンバーは未知のフィールドを許さずにデコードするので、オブジェクトがどのstructにも一致してしまうことはありません。必須のフィールドは検査しません |
| 必須のプロパティ | デコード時に検査しません。値がなければゼロ値になります |
| nullを許す必須のプロパティ | 値がなければ `nil` にデコードします |
| `const` | そのスカラー型 |
| タプル | `[]any` |
| 文字列と数値の制約、`oneOf` の排他性 | 検査しません |
| 小数で書かれた整数（`1.0`） | `encoding/json` が拒否します |
| structのタグに書けない名前のプロパティ（`"`、`\\`、`,`、`'`、バッククォートを含むもの、または空のもの） | 警告を出して省きます |
| タグ付きのunion | 値を受け取る箇所では `Unknown` を加えます。名前付きの型はどの値も保持できるので、enumに受け皿は要りません |

## レイアウトと命名 {#layout-and-naming}

出力先ディレクトリに1つのパッケージを出力します（Goでは、importの循環なしに1つのパッケージを複数のディレクトリに分けられません）。宣言ごと（`pet_gen.go`）と操作ごと（`get_pet_by_id_op_gen.go`）に1ファイル、それにパッケージのドキュメントとランタイムのバージョンを持つ `tsurara_gen.go` です。ファイル名は `_gen.go` で終わるので、ビルド制約（`_linux.go`、`_test.go`）で終わる名前にはなりません。すべてのファイルはGoのツールが認識する行 `// Code generated by tsurara. DO NOT EDIT.` で始まり、`gofmt` と同じ形（フィールド、タグ、コメントの桁揃え）で出力されます。バックエンドはフォーマッターを実行しないためです（18.8）。説明文はインデントと空行を除いた `//` コメントになるので、gofmtが書き換えるコードブロック、リスト、見出しは生じません。

すべてをexportします。型、フィールド、定数、関数はPascalCaseで、Goの頭字語（`ID`、`URL`、`HTTP`、`JSON`、`API` など、golintが挙げるもの。複数形も含む：`PetID`、`PhotoURLs`、`GetPetByID`）を使います。最初の文字に大文字がない名前には `X` を付け（`X日本語`）、数字で始まる名前には `V` を付けます。enumの定数は型名と値をつなげた名前です（`PetStatusAvailable`）。これらはすべて同じパッケージのスコープを共有します。関数は操作の名前を保ちます。同じ名前のスキーマは名前をずらし、その操作のリクエストの本文なら `{Name}Body`（`toggleAll` とスキーマ `ToggleAll` なら `ToggleAll(ctx, c, body ToggleAllBody, nil)`）、それ以外なら `{Name}Model` になります。ほかの衝突は、名前を確保した順（型、定数、関数）に番号を付けます。Goのキーワードと事前宣言された識別子は小文字なので、exportされた名前がそれらと衝突することはありません。変わるのは、空になる名前と数字で始まる名前（`V1`）だけです。フィールドはstructごとに命名され、struct自身が使う名前（`AdditionalProperties`）を避けます。JSONのキーはタグに入ります。

## 呼び出し関数と結果 {#call-functions-and-results}

```go
func GetPetByID(ctx context.Context, c *tsurara.Client, petID int64, opts *GetPetByIDOptions) (*tsurara.Success[Pet], error)
```

- ドキュメントコメントは関数名で始まり（`// GetPetByID calls GET /pet/{petId}.`）、概要と説明が続きます。
- contextは呼び出しをキャンセルし、期限を運びます。必須のパラメーターと必須の本文は引数です。省略可能なものはすべて `{Operation}Options` のポインターのフィールドで、`opts` は `nil` でも構いません。
- メディアタイプが複数ある本文は、メディアタイプごとにポインターを持つラッパーのstruct `{Operation}Body` です（`JSON *Pet`、`Form *Pet`、`OctetStream *tsurara.File`）。設定されたフィールドが `Content-Type` を決めます。
- `*tsurara.Success[T]` は `Status`、`Data T`、`Headers`、`Operation` を持ちます。`T` は成功時の本文の型です。内容のないレスポンスは `struct{}`（またはもう一方のレスポンスの型のゼロ値）、型が異なれば `any` です。JSONのメディアタイプを持つレスポンスはJSONとして読まれます（Rustと同じ）。バイナリのレスポンスは `[]byte`、テキストのレスポンスは `string` です。
- 項目のスキーマ（`itemSchema`、または3.2より前の `x-itemSchema`。design.md 8.5）を持つServer-Sent Events、JSON Lines、JSON text sequencesは、すべての成功レスポンスが項目ごとに読まれる場合、`*tsurara.Success[*tsurara.Items[T]]` になります。関数は `tsurara.DoItems` を呼び、ヘッダーが届いた時点で戻ります。項目は `for item, err := range s.Data.All()` で読みます。イベントは、イベントごとにポインターを持つunionのラッパー（`StreamEvent{StreamNoteEvent *StreamNoteEvent; ...; Unknown json.RawMessage}`）で、`event` で選ばれます。1つのイベントに複数の名前があれば、定数付きの名前付き型になります（`MixedPingEventNamePong`）。ループを抜けるとレスポンスが閉じ、`Close` は読まずに閉じます。クライアントのタイムアウトは項目の読み取りには及びません（contextは及びます）。ストリームと並んでJSONのメディアタイプがあれば、その操作は上のとおりJSONとして読まれます。
- エラーは、成功以外の契約のすべての結果について `*tsurara.Failure[E]` です。`Kind`（`tsurara.KindHTTP`、`KindNetwork`、`KindTimeout`、`KindParse`、`KindUnexpected`、`KindAborted`）、`Status`、`Documented`（定義にあるエラーの本文 `E` があればそれ、なければ生の本文）、`Cause` を持ちます。unwrapすると原因になるので、`errors.Is(err, context.Canceled)` が使えます。`var failure *tsurara.Failure[Problem]` に対する `errors.As(err, &failure)` で、その操作の定義にある本文が得られます。`var f tsurara.AnyFailure` はどの操作の失敗も読め、`f.Info()`（`Kind`、`Status`、`Documented`、`Headers`、`Cause`、`Operation`）を持ちます。
- OperationDefは `spec/operation-def.schema.json` のJSONで、文字列として埋め込まれ、1回だけ解析されます（`sync.OnceValue`）。
- `tsurara_gen.go` には、コードが必要とするランタイムのバージョンが記録されます（`// Requires github.com/tsurara-openapi/tsurara/runtimes/go v0.1.0`）。`tsurara check` は、それを最も近い `go.mod` の要求（同じマイナーバージョン）と比べます。`replace` ディレクティブで別の場所を指しているモジュールについては、報告するだけにとどめます。
- 引数はlowerCamelCase（`petID`）です。Goが予約している名前や関数が使う名前（`type`、`string`、`ctx`、`opts`）には番号が付きます（`type2`）。Optionsのフィールドは、structのフィールドと同じくexportされます。

## クライアントなしで型だけを使う {#types-without-the-client}

`operations: false` では、パッケージは宣言だけを持ちます。操作のファイルはなく、`net/http` や `context` をimportするものもありません。ランタイムは1つのパッケージのままで、生成された型はそのunionのヘルパー（`types.go`、`value.go`）だけを使います。何もクライアントを呼ばなければ、リンカーがクライアントを取り除きます。型はただの `encoding/json` の型です。

```go
var pet petstore.Pet
err := json.Unmarshal([]byte(`{"id":1,"name":"Pochi"}`), &pet)
```

## モック {#mocks}

`go.mocks: true` にすると、ビルドタグ `tsurara_mocks` 付きの `mocks_gen.go` が生成されたパッケージに入ります。本番のビルドではこれが除かれ、テストは `go test -tags tsurara_mocks` で実行します。

- `Mock{Type}()` は各宣言のサンプル値をデコードします。
- 操作ごとに、定義にあるステータスごとのコンストラクター（`ShowPetByIDMock200(body Pet)`、`ShowPetByIDMockDefault(status int, body Error)`）と、`tsuraratest` 向けの `ShowPetByIDRoute(respond)`（nilなら定義にある最初の成功レスポンス）があります。`MockRoutes()` はすべての操作を並べます。

モックの名前は、パッケージのほかのすべての名前のあとに確保されます。そのため、モックを有効にしても生成コードの名前は変わりません。

## 使い方 {#using-it}

モジュールのディレクトリに生成し（`output: internal/petstore`）、ランタイムを追加して（`go get github.com/tsurara-openapi/tsurara/runtimes/go`）、関数を呼び出します。

```go
c := tsurara.NewClient("https://petstore3.swagger.io/api/v3")
pets, err := petstore.FindPetsByStatus(ctx, c, petstore.FindPetsByStatusStatusAvailable, nil)
if err != nil {
	return err
}
for _, pet := range pets.Data {
	fmt.Println(pet.Name)
}
```
